General rules

RuleDetail
Hover is one changeOnly the element under the pointer changes: its border or line turns dashed --sel-hov. Neighbours don't change, and there's no fill change, glow or ring.
Hover on selectedNothing changes, only the cursor.
Hover on connectedGets the hover look over the connected look. It goes back to connected when the pointer leaves.
Hover on dimmedThe card's content goes back to full opacity with the dashed border, so you can read it. The neighbours stay dimmed.
Connections show on clickHover never previews connections. Connected only appears after a click.
Connected cardsNo extra border, ring or colour. They just stay at full opacity while the rest dims.
Connected arrowsTurn --rel and solid, except suggested arrows, which keep --warn dashed. Their chips use --chip-rel.
One selectionOnly one element is selected at a time, card or arrow, never a group.
Selecting an arrowThe arrow is selected and the two cards at its ends are connected.
ClearingClick the selected element again, click empty canvas or press Esc.
Selection beats colour at restA selected element is --sel, even when it's red for impact or yellow for clarification.
Never dimmedThe canvas, lanes, lifelines, their headers, legends and the zoom bar.
TooltipsAllowed on hover. A tooltip isn't a state.
KeyboardFocus looks like hover. Enter selects, Esc clears.

Fix needed: double hover and selection states

What happens in the dev environment

Hovering in the Galaxy changes two or three things at once. The element gets an outline, its fill or width changes too, and its neighbours light up while the rest dims. It looks like two colours fighting. An element must show one state at a time, like the context diagram does.

Causes found in the prototype

  1. Hover previews connections. preview() runs on mouseover, adds pvhi to the neighbours and pvdim to the rest. With the .hov outline, that's two states from one hover. Connections should only show on click.
  2. Hover is defined five times. There are separate .el.hov rule sets in the base Galaxy styles, the Galaxy layer, the old orange theme, the first --sel-hov pass and the dashed pass. They stack, so one hover gets a fill, a width and a dash at the same time.
  3. Hover changes the fill. .el[data-k=ctx].hov .arc sets a lighter fill (#4a5063 or --surface-strong-h) as well as the outline. The lighter fill is the connected look, so hover reads as connected.
  4. Hover changes widths. stroke-width:2.2 on external boxes, 3.4px on integrations while something is selected.
  5. Peek while selected. Hovering a dimmed element adds peek as well as hov.
  6. Old cards rules. The context diagram card has three hover rules (outline, ring, dashed border) in different blocks. Only the last one should exist.

Fix

  1. One function sets one state class on each element: rest, hov, sel, rel or dim, picked by the priority above.
  2. Delete the old rule sets. Keep one per state, as in the tables above.
  3. Remove the hover preview, or move it to click.
  4. Hover changes the border or line only: no fill, no width on cards, no ring.
  5. Apply the same to the sequence diagram, flowchart, swim lane and Teams.

How to check: hover each element type in each diagram, with and without a selection. Only the element under the pointer should change.
